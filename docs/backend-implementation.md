# 백엔드 1차 구현 기록

## 작업 범위

백엔드는 논문 수집·파싱·추출 단계에서 저장한 데이터를 제공한다. 1차 구현에서는 `mock/*.json` 파일을 로컬 SQLite 데이터베이스에 적재해 사용한다. API는 조회 전용이며, 논문 수집이나 NLP 처리는 담당하지 않는다.

## 로컬 실행 방법

Python 3.10 이상이 필요하다.

저장소 루트 폴더에서 다음 명령을 실행한다.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m backend.scripts.seed
uvicorn backend.app.main:app --reload
```

기본 데이터베이스 경로는 `data/reading_verifier.sqlite3`이다. `READING_VERIFIER_DB` 환경 변수로 다른 로컬 SQLite 파일을 지정할 수 있다. 데이터베이스 파일은 로컬에서 생성하며 Git에 커밋하지 않는다.

## 데이터 모델 설계 결정

- `papers`, `sentences`, `claims`를 별도 테이블로 두고 `paper_id`로 연결한다. 문장의 식별자는 `(paper_id, idx)` 조합이다.
- 저자, 분야 분류, claim의 목록과 같은 값은 SQLite 텍스트 열에 JSON으로 저장한다. 1차 구현의 구조를 단순하게 유지하면서 API에서는 배열과 객체 형태로 제공하기 위해서다. 조회 요구가 늘어나면 별도의 관계형 테이블로 분리할 수 있다.
- `fulltext_path`, `source_format`, `fetched_at`은 수집 과정에서 사용하는 내부 메타데이터로 저장한다. 응답 변환 코드가 공개할 필드만 선택하므로 로컬 파일 경로는 API 응답에 포함되지 않는다.
- 목데이터 적재 스크립트는 논문 정보를 기본 키 기준으로 갱신하고, 현재 JSON에 없는 해당 논문의 문장·claim만 정리한다. 전체 작업은 하나의 트랜잭션으로 처리하며, 목데이터에 없는 다른 논문 레코드는 건드리지 않는다.
- DB 연결은 잠금이 발생하면 최대 10초 동안 기다린다. WAL 모드는 DB 초기화 때 설정해 API 조회와 적재 작업의 동시 접근을 지원한다.
- 논문 상태, 문장 역할, claim 신뢰도, `claim_id` 형식은 DB에서도 검증한다. 기존 로컬 DB에도 트리거로 같은 검증을 적용한다. seed는 claim의 주장·근거·조건·유보 문장 번호가 같은 논문의 실제 문장을 가리키는지 적재 전에 확인한다.
- 날짜 범위에서 시작일이 종료일보다 늦으면 `422`를 반환한다.
- 목록 API는 카테고리를 SQLite의 `json_each` 함수로 필터링하며, 응답에 공개하지 않는 내부 열은 SQL에서 읽지 않는다.
- 조회 결과는 일관된 순서로 반환한다. 논문은 발행일 내림차순으로, 문장과 claim은 숫자 인덱스 오름차순으로 정렬한다.

## API 규약

- `GET /papers?category=cs.CL&from=2026-10-01&to=2026-11-30`
- `GET /papers/{paper_id}`
- `GET /papers/{paper_id}/claims`

존재하지 않는 ID에는 상태 코드 `404`와 `{"error":"paper_not_found"}`를 반환한다. 날짜 필터 형식이 올바르지 않으면 `422`를 반환한다. claims API는 목록이 비어 있어도 논문의 처리 상태를 함께 반환한다. 이를 통해 추출이 완료됐지만 claim이 없는 상태(`extracted`)와 아직 추출 작업을 하지 않은 상태(`parsed`)를 구분할 수 있다.

## 이후 파이프라인과 연동

논문 수집기·파서·추출기가 같은 세 가지 레코드 형식을 사용해 공유 데이터베이스에 기록하도록 연결한다. 추후 SQLite 대신 다른 데이터베이스를 사용하더라도 API 규약과 응답 변환은 유지하고, 데이터베이스 연결 부분과 배포 설정을 변경하는 방향을 목표로 한다. 재파싱하면 문장 인덱스가 달라질 수 있으므로 claim과 문장의 연결에 파서 버전을 어떻게 반영할지는 팀에서 추가로 결정해야 한다.
